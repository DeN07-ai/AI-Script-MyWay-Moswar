# ЧАСТЬ I. ИТЕРация 8 (2026-11-20) — АКТУАЛЬНОЕ СОСТОЯНИЕ

## 1. Аппаратный клик

Юзерскрипт **не подделывает** событие. Он просит внешний локальный процесс
кликнуть по кнопке; событие рождается вне страницы, поэтому браузер помечает
его `isTrusted: true`.

Путь на macOS:

```
userscript → POST http://127.0.0.1:3999/click
           → companion/companion.js
           → bin/mw_clicker_mac --click
           → Accessibility (AXWebArea) = реальная геометрия viewport
           → CoreGraphics kCGHIDEventTap (move → down → up)
           → страница получает isTrusted: true
```

| Файл | Назначение |
|------|-----------|
| `companion/macos_clicker.c` | Нативный кликер (C, только системные фреймворки). Режимы: `--status`, `--windows`, `--probe/--click`, `--find/--find-dry`, `--dump`, `--close-window`, `--prompt` |
| `companion/companion.js` | HTTP-сервер на 3999. Сам компилирует кликер, сам находит PID браузера |
| `companion/install-mac.sh` | Установка: сборка + LaunchAgent + проверка готовности |
| `companion/companion-mac-status.sh` | Диагностика «готов ли кликать прямо сейчас» |
| `companion/selftest/` | Тестовая страница, считающая только `isTrusted === true` |

Масштаб страницы (80 % / 100 % / 110 %) **не влияет** на попадание: реальный
масштаб считается из геометрии как `AXWebArea.width / window.innerWidth`,
`devicePixelRatio` — только запасная оценка. Проверено: при `innerWidth=1084`
и ширине web-области `867` кликер вычисляет `zoom=0.7998`.

Результаты теста:

| Проверка | Результат |
|---|---|
| AX-клик по координатам кнопки | `m11 d1 u1 b103` — один trusted down/up и один trusted click по кнопке |
| Точка клика vs центр кнопки из AX | `(149,368)` против `(149.5,368.5)` — совпадение |
| Companion из-под launchd | `clickReady: true` после выдачи Accessibility для node |

## 2. Исправлен акционный (meld) режим

Реализованный эталон:

```
пришли в страну
  → прочитали акционный дроп
  → дроп ≥ порога → бой
  → дроп < порога:
        перебор включён  → сменили противника → СРАЗУ перечитали дроп → бой
        перебор выключен → следующая страна
        перебор исчерпан → следующая страна
  → вернулись из боя → перечитали дроп → нет → следующая страна
```

| № | Было | Стало |
|---|------|-------|
| 1 | `goToCountry()` вызывался **на каждой** итерации `handleMeldMode()` и перезагружал блок travel2, сбрасывая результат перебора → бесконечный перебор вместо перехода | Переход только при первом входе в страну |
| 2 | После клика перебора новый дроп в этом же вызове не читался | Перечитывается сразу после `waitAfterReroll()` |
| 3 | `gotoNextCountryInMeld()` вызывался **сразу после старта боя**, до его конца → `lastFightCountry !== currentCountry` → результат боя терялся | Переход после боя убирается; результат обрабатывает `mainLoop` |
| 4 | Обработка победы для `mode === "meld"` была пустой | Победа → `meldPostFightCheck = true` → перепроверка дропа → при отсутствии следующая страна |
| 5 | Обработка результата привязана к совпадению стран, `syncCurrentCountryFromSelector()` мог их развести | Для `meld` результат обрабатывается независимо от совпадения |
| 6 | «Нет билетов смены» показывалось и при выключенном переборе | Сообщения разделены |

Новое состояние: `meldPostFightCheck` (~4011), сбрасывается в
`gotoNextCountryInMeld()` и в `startBot()`.

Изменённые функции: `handleMeldMode()`, `gotoNextCountryInMeld()`,
`startBot()`, `mainLoop()` (блок «ОБРАБОТКА РЕЗУЛЬТАТА ПОСЛЕДНЕГО БОЯ»).

## 3. Что сознательно не менялось

- **Поражение в акционном режиме** — остаёмся в стране до победы, как и в
  остальных режимах. Если дроп всё ещё ≥ порога, бой повторится. Отдельную
  настройку «уходить после поражения» не добавлял — это продуктовое решение.
- Режимы `cycle`, `strong`, `farm` не тронуты.
- `startBossFight`, классификация отказов, лимиты билетов — без изменений.

## 4. Проверки и ограничения

Выполнено: `node --check` (оба файла), сборка кликера без предупреждений,
`build-release.mjs` + `--check` (мост синхронизирован, 3.18), `curl /status` →
`clickReady: true`.

**Не проверено в живой игре:** акционный режим после правок. Это обязательный
следующий шаг — прогон на 2–3 странах дважды: с включённым и с выключенным
перебором противников.

## 5. Следующие шаги

1. Ручной тест акционного режима в игре.
2. **Фоновая и многопрофильная работа.** Установлено эмпирически:
   - AX-клик **требует активного окна**: он поднимает окно (`AXRaise`) и бьёт по
     экранным координатам; свёрнутое окно валидной геометрии не имеет. Фоновая
     работа и параллельные профили на этом пути невозможны в принципе.
   - **CDP работает в любом состоянии окна.** На тестовой странице, считающей
     только `isTrusted === true`: активное окно `d0→d1`, неактивное `d1→d2`,
     свёрнутое `d3→d4`.
   - Вывод: для фона и параллельности нужен CDP, то есть браузер, запущенный с
     `--remote-debugging-port`. Chrome 136+ запрещает отладку профиля по
     умолчанию, поэтому нужен отдельный `--user-data-dir` и одноразовый логин в
     нём. Сам клик через CDP может слать юзерскрипт (WebSocket), Companion для
     этого не обязателен.
3. **Пользователь без установки окружения.** Текущий AX-путь требует Node +
   clang + ручное разрешение Accessibility, поэтому у второго пользователя без
   установки не работает. Решение — пункт 2 плюс launcher-ярлык.
4. Починить `companion/launch-chrome-mac.sh`: `open -a --args` игнорирует флаги
   у уже запущенного Chrome, `*` без кавычек раскрывается shell'ом.

# ЧАСТЬ II. АРХИВ — итерация 7 (2026-11-14)

## 7. Задача и цель
Пользователь:
«проверь наш скрипт - убери все функции и упоминания clickProof
данный метод не несет в себе эталонное поведение ,а только делает наш код грязным
нам нужно рабочее чистое решение ,которое будет эталонным и применимым в дальнейшем»

Цель:
1. Полностью удалить все упоминания, вспомогательные функции, комментарии и искусственные проверки окружения clickProof.
2. Отказаться от глобального загрязнения среды (никаких `@run-at document-start`, `GM_addElement`, патчей `Worker`, `EventTarget`, `JSON`, `WeakMap`).
3. Реализовать чистое, эталонное решение запуска боя: точечный вызов функции игры `Worldtour2.startFight(proxyEvent)` с локальным изолированным объектом события (Вариант А).

## 2. Что реализовано (фактические изменения, версия 3.17)
